01

研究章程：先定义“可行”的含义

避免把数据库能力对比误当成系统级可行性结论。
边界声明：本文只提供分析框架、验证问题、实验设计和结论模板；不会判断 FoundationDB 适合或不适合。真实目标环境中的可复现实测是唯一衡量标准；源码、官方文档、理论推演、实验室模拟和通用 benchmark 只能形成待验证假设，不能计分，也不能支撑最终可行性结论。

核心决策问题

在满足 pNFS/NFSv4 元数据正确性、目标性能、故障恢复与运维约束的前提下，是否值得将当前 RonDB / MySQL NDB 后端替换为 FoundationDB？若值得，应采用何种数据模型、接入方式和迁移策略？

必须提前量化的验收线

  • 不可妥协的正确性与一致性条件
  • 关键操作的吞吐、P50/P95/P99 延迟预算
  • 允许的故障窗口、RTO、RPO 与降级行为
  • 迁移停机窗口、回滚时间与数据校验标准
  • 三至五年总成本、团队技能与支持要求

“真实目标环境”的最低定义

基础设施真实

使用目标生产版本、服务器规格、CPU/内存/磁盘、网络链路、故障域、安全配置以及实际部署拓扑。

数据与流量真实

使用脱敏生产数据或经校验等价的数据全集，并回放真实操作组合、热点分布、并发、峰值、后台任务和增长模式。

运行条件真实

纳入真实客户端、MDS/DS 数量、监控告警、值班流程、升级恢复、资源争用与计划内外故障；保留完整原始证据。

若任一关键条件与目标生产环境不一致，该结果只能标记为“预验证”，不得进入评分。无法在生产系统直接注入的破坏性故障，应在与生产配置一致、经环境等价性验收的隔离真实集群中执行，并明确记录唯一差异。

IN SCOPE

生产语义

命名空间、状态、布局、协调、GC、注册表等全部生产数据路径。

IN SCOPE

全生命周期

开发、部署、升级、扩容、备份恢复、监控、应急与迁移。

OUTCOME

多种结论

不是简单二选一，允许全量替换、局部采用、延后或否决。

EVIDENCE

实测唯一

只有真实目标环境中的可复现实测可作为结论证据；其他材料仅用于准备验证。

03

十三个分析维度

每个维度都要产出：问题 → 证据 → 方法 → 判定条件。
1. 功能覆盖与接口契约FUNCTION

关键问题

  • 所有 authority / coordination vtable 操作能否表达？哪些仅在 RonDB 实现中隐含？
  • 错误码、幂等性、可选能力、事务嵌套与回调行为是否等价？
  • 管理、诊断、搜索、catalog image 和工具链是否依赖 SQL/NDB 特性？

验证方法

生成接口清单与调用图；逐操作建立“现状语义—候选实现—测试用例”追踪矩阵；对 fallback 路径单独标记。

产出 / 闸门

100% 接口归类；所有 Must-have 有实现路线及自动化验收；任何未覆盖操作不得被“可编译”掩盖。

2. 数据模型与键空间设计MODEL

关键问题

  • inode、dirent、状态表、二级索引和计数器如何编码为键值与有序子空间？
  • 路径深度、大目录、长文件名、xattr、热点父目录如何影响键长、值大小与分片？
  • 版本、schema 演进、兼容读取、孤儿与索引修复如何设计？

验证方法

画 keyspace 与访问路径；按操作估算读写集合、字节数和冲突范围；构造倾斜/热点数据集。

产出 / 闸门

Keyspace 规范、编码规范、索引维护规则、版本策略，以及每个访问模式的成本表。

3. 事务、一致性与并发语义CORRECTNESS

关键问题

  • create/remove/rename/link/setattr/nlink 调整的跨记录不变量是什么？
  • 读写冲突、原子计数、CAS、锁语义与当前行锁/解释更新如何对应？
  • 事务冲突重试后，NFS 请求副作用、外部 DS 操作和响应重放是否仍幂等？
  • 事务大小、持续时间、读版本保留和单操作放大是否越界？

验证方法

为每个复合操作画事务时序图；建立不变量清单；高并发交错测试、故障点注入和历史一致性检查。

产出 / 闸门

事务语义映射、冲突处理规范、重试预算；零已知不变量破坏，冲突率与尾延迟在验收线内。

4. 性能与可扩展性PERFORMANCE

关键问题

  • 单操作 round trip、批量/范围读、读写放大与序列化成本如何变化？
  • 单父目录、单文件、全局 fileid、队列头部等热点上限在哪里？
  • MDS 横向扩展后数据库吞吐、冲突率、P99/P99.9 是否线性或可预测？
  • 大目录 READDIR、扫描/搜索和后台 GC 是否干扰前台业务？

验证方法

同硬件、同数据、同客户端的 A/B 基准；微基准 + NFS 端到端 + soak；记录服务时间分解与数据库内部指标。

产出 / 闸门

基线对比、扩展曲线、容量模型、热点画像、资源效率及可解释的瓶颈归因。

5. 可靠性、可用性与故障语义RESILIENCE

关键问题

  • 进程、主机、磁盘、网络分区、丢包/延迟、机架与站点故障的外显行为是什么？
  • 仲裁、复制、故障域、读写可用性与数据持久性目标如何配置和证明？
  • MDS 与数据库故障时的超时、退避、熔断、恢复风暴和客户端错误映射是否合理？

验证方法

基于故障树的 chaos 矩阵；在负载中注入故障；校验线性化历史、RTO/RPO、积压与自动恢复。

产出 / 闸门

故障模式表、可用性预算、恢复证据与人工步骤清单；未知故障语义必须显式登记。

6. NFSv4 / pNFS 协议正确性PROTOCOL

关键问题

  • stateid、sequence slot、open/lock owner、delegation、layout recall/return 如何跨 MDS 持久化？
  • 重放、重复请求、MDS 重启、grace/reclaim 和客户端恢复是否与后端重试组合正确？
  • 目录 cookie、change attribute、文件句柄稳定性与 rename/link 语义是否保持？

验证方法

协议覆盖矩阵；Linux 客户端互操作；多 MDS 并发；网络中断、重启与重放测试；抓包对照。

产出 / 闸门

协议场景测试报告、状态机覆盖率、错误映射表和恢复证明。

7. 运维、可观测性与可支持性OPERATIONS

关键问题

  • 安装、拓扑、配置、扩缩容、滚动升级、证书、备份恢复与容量预警复杂度如何？
  • 是否有生产所需指标、trace、日志、诊断包、慢事务和热点定位能力？
  • 团队能否值守；上游社区、商业支持、版本节奏与生命周期是否匹配？

验证方法

由非实现作者在真实目标环境按 runbook 独立部署与恢复；计时并记录人工决策点；以真实告警完成故障定位。

产出 / 闸门

生产 runbook、监控面板、告警规则、升级/回滚演练记录与技能差距计划。

8. 数据迁移、兼容与回滚MIGRATION

关键问题

  • 全量导入、增量追平、双写、影子读或停机迁移分别需要什么前提？
  • 如何生成一致快照、保存版本/状态、校验引用完整性并处理切换期间写入？
  • 回滚会不会丢失新后端独有写入；回滚点与不可逆点在哪里？

验证方法

生产量级数据迁移彩排；逐表/逐不变量校验；切换与回切演练；注入中断、重复和乱序。

产出 / 闸门

迁移方案、校验器、状态机、时间预算、Go/No-Go 清单和可演练回滚路径。

9. 安全、合规与供应链SECURITY

关键问题

  • 认证、传输/静态加密、最小权限、租户隔离、密钥轮换与审计是否满足要求？
  • C/C++ 客户端依赖、打包、SBOM、漏洞响应、许可证与再分发条件有何影响？
  • 备份、日志、诊断数据是否暴露文件名、UID/GID 或访问模式？

验证方法

威胁建模、配置审计、依赖扫描、许可证审查、凭证轮换和越权测试。

产出 / 闸门

威胁与控制矩阵、依赖清单、法律审查结果、残余风险签署。

10. 工程集成与长期维护ENGINEERING

关键问题

  • 新增后端是否真正局限于 vtable/factory，还是存在 RonDB 旁路与硬编码？
  • C API、线程模型、连接/事务池、异步能力、取消和 shutdown 如何接入？
  • 测试替身、CI、跨平台构建、包体、升级兼容和调试体验成本如何？

验证方法

dependency scan；实现最小垂直切片；评审代码增量、耦合、测试覆盖和错误处理。

产出 / 闸门

组件设计、改动热区、估算与风险区间、维护责任边界和弃用计划。

11. 成本、容量与资源效率ECONOMICS

关键问题

  • 计算、内存、磁盘、网络、备份、跨域流量和冗余容量的三至五年 TCO 如何？
  • 为满足相同 SLO，各方案需要多少节点、预留和工程投入？
  • 迁移期间双集群、双写、压测环境与培训支持的成本是否计入？

验证方法

基于实测资源曲线建模；给出基准/高增长/故障冗余三种情景；做敏感性分析。

产出 / 闸门

统一口径 TCO、单位成本（每百万操作/每十亿对象）、峰值容量和不确定性区间。

12. 战略适配、生态与退出成本STRATEGY

关键问题

  • 候选方案是否支持未来分片、多地域、更多元数据服务和云/本地部署方向？
  • 专用 keyspace、绑定 API 或运维工具会形成何种锁定？
  • 若未来再次迁移，数据导出、抽象层和兼容协议能否降低退出成本？

验证方法

三年路线图访谈；退出演练设计；对关键上游依赖做成熟度和 bus factor 评估。

产出 / 闸门

战略契合度、可逆性设计、依赖风险与触发重新评估的条件。

13. 异常处理与错误语义ERROR HANDLING

关键问题

  • 数据库异常如何分为可重试、不可重试、调用方错误、数据损坏、资源耗尽和运维配置错误？
  • FoundationDB 客户端错误如何稳定映射到内部 mds_status、NFSv4 错误码以及管理接口响应，是否会误报或吞错？
  • 事务冲突、超时、未知提交结果、版本过旧、网络中断、集群不可用时，重试是否满足次数、总时限、退避、抖动与取消约束？
  • 重试后 create/remove/rename、状态更新、GC 入队和外部 DS 副作用是否保持幂等，未知提交结果如何对账？
  • 部分成功、进程崩溃、队列毒任务、数据解码失败、schema/版本不兼容和资源耗尽时如何隔离、补偿或安全停机？
  • 异常是否携带 operation、transaction、fileid/clientid、重试次数与根因链等诊断上下文，同时避免泄露敏感数据？

验证方法

建立错误分类与映射表；在事务边界和每个外部副作用前后设置故障点；注入冲突、超时、断网、未知提交结果、损坏值、OOM/磁盘满模拟及配置错误；验证重试、补偿、熔断、降级、告警和恢复。

产出 / 闸门

错误目录、映射规范、重试策略、异常时序图、补偿与人工处置 runbook；禁止无限重试、静默数据丢失、错误码漂移及无法判定的重复副作用。

05

六阶段执行方法

从事实盘点逐步推进，前一阶段不通过则不扩大投入。
PHASE 0冻结目标场景、规模、SLO、版本、硬约束、权重与决策人。
PHASE 1现状取证接口、事务、不变量、数据量、性能、故障与运维基线。
PHASE 2纸面映射keyspace、访问路径、事务预算、能力差距与风险假设。
PHASE 3预验证实现实现高风险操作族、校验器和故障点；结果只用于完善真实实验。
PHASE 4真实环境验证在目标条件下完成端到端性能、长稳、故障、恢复、运维与迁移彩排。
PHASE 5决策评审证据评级、评分、残余风险、方案选择与下一步。

决策证据：REAL

真实目标环境的可复现实测。 环境等价性记录、自动化脚本、生产型数据与流量、原始结果、版本和责任人齐全；这是唯一允许计分和形成结论的证据。

准备材料：REFERENCE

源码与权威文档。 仅用于识别接口、不变量、能力边界和设计实验；未经真实环境验证不得转化为评分或结论。

待证假设：HYPOTHESIS

PoC、模拟、通用 benchmark、推断、访谈或经验。 只负责产生验证任务；即使结果良好也不得支撑 Go/No-Go。

优先验证高风险假设：预验证顺序可从跨目录 rename、热点目录并发、READDIR 分页、状态重放、后台队列 claim、MDS/数据库故障恢复开始；但最终必须在真实目标环境重新完整执行。不要以单键 get/set、实验室 PoC 或模拟结果替代系统判断。

实验矩阵与度量规范

实验必须可比较、可复现、可解释。

真实环境统一实验设计

  • 使用真实目标硬件、网络、MDS/DS 配置、客户端与生产型数据集；记录所有版本、参数与环境差异。
  • 预热、测量、冷却阶段分离；至少多轮运行并报告方差和置信区间。
  • 负载从单客户端逐级扩展到瓶颈；同时测试均匀与 Zipf/热点分布。
  • 前台/后台、读/写、操作类型按生产占比混合；保留单操作诊断基准。
  • 原始结果、日志、trace、配置、脚本与 commit SHA 一并归档。

用户面

成功率、NFS 错误码、ops/s、P50/P95/P99/P99.9、超时与重试。

数据库面

事务提交/冲突/重试、读写字节、延迟、热点、队列、存储与网络。

正确性面

不变量检查、丢失/重复、孤儿、索引差异、状态泄漏与恢复完整性。

迁移策略的验证树

先验证可逆性，再讨论上线速度。

停机迁移

适用于可接受明确停机窗口的情景。重点测量一致快照、导入速率、校验和回滚总时长。

全量 + 增量追平

重点验证变更捕获的完备顺序、切换水位、重复应用与追平期间的写放大。

双写 + 影子读

重点验证原子性缺口、失败补偿、差异检测、对线上延迟的影响和双写退出条件。

按域 / 分区渐进

重点验证跨后端事务、路由、共享状态和跨边界 rename/link 是否允许渐进切换。

评分不能覆盖的硬闸门

  • 任一关键维度缺少真实目标环境验证，整体结论只能是“证据不足”
  • 任何协议/数据不变量无法满足
  • 关键场景无法回滚或无法验证数据一致
  • 关键 SLO 在目标规模下不可达
  • 存在无限重试、错误码误映射、未知提交结果无法对账或重复副作用风险

  • Go：全量替换，进入工程化与生产试点

  • Hybrid：仅在部分责任域或新场景采用
  • Defer / No-Go：延后复评或维持现状，并记录触发条件
