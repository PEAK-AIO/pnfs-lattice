## 0. 为什么是提案而不是"已冻结"

计划自身把"冻结评分权重"排在启动清单末段，且 §08 明确"权重在实验前冻结、可由决策委员会调整至合计 100"。分析侧的职责是**给出可直接签署的草案 + 每一项的依据**，让决策方一次签完；分析侧单方面宣布"已冻结"会越权，且与计划"避免预设技术结论"的边界声明冲突。因此本文件 = 草案 + 决策点清单。

## 1. 证据等级（三档，已对齐计划 §05，可直接冻结）

| 等级 | 定义 | 能否计分/支撑结论 |
|---|---|---|
| **REAL** | 真实目标环境可复现实测：环境等价性记录、自动化脚本、生产型数据与流量、原始结果、版本、责任人齐全 | **唯一**允许计分并进入 §08 评分 |
| **REFERENCE** | 源码与权威文档；本阶段所有 `docs/fdb-feasibility-*` 取证均属此档 | 只能形成待验证假设，**不得**转化为评分 |
| **HYPOTHESIS** | PoC、模拟、通用 benchmark、推断、访谈 | 只产生验证任务，**不得**支撑 Go/No-Go |

**强制规则**：任何实验产物归档时必须带 `evidence_class` 字段（见 `fdb-feasibility-02` §B.3 manifest 约定）；评分表（§08）只允许填 REAL 对应的维度，未做真实验证的维度保持"待评"。**这条可直接冻结**（是计划硬闸门"任一关键维度缺真实验证→结论只能是证据不足"的落地）。

## 2. 评分维度与权重（草案，合计 100）

计划 §08 列出 10 个评分维度（权重留 `—`）。依据"pNFS 元数据后端的失败代价"排序：**正确性/协议 > 一致性/事务 > 性能 > 可靠性 > 异常/迁移/运维**。草案权重：

| # | 维度（对齐计划 §03 十三维度） | 草案权重 % | 评分锚点（0–5） | 对应计划维度 |
|---|---|---|---|---|
| 1 | 功能与协议正确性（NFSv4/pNFS 状态机、重放、grace） | 20 | 0=协议不变量破坏;3=最低线全过;5=协议覆盖率+零已知破坏 | 维度6 |
| 2 | 事务与一致性（跨记录原子不变量、冲突、CAS） | 18 | 0=I-1..I-9 有破坏;3=零破坏+冲突在预算;5=含故障注入仍零破坏 | 维度3 |
| 3 | 性能与扩展（P50/P99、热点上限、多 MDS 线性度） | 15 | 0=关键 SLO 不可达;3=达标;5=线性可预测+热点受控 | 维度4 |
| 4 | 可靠性与恢复（故障模式、RTO/RPO、恢复风暴） | 12 | 0=故障后不可恢复;3=逐故障达标;5=含分区/站点隔离 | 维度5 |
| 4→ 5 | 异常处理与错误语义（错误映射、有界重试、未知提交对账） | 8 | 0=无限重试/吞错;3=有界+映射稳定;5=含未知提交对账 | 维度13 |
| 5→ 6 | 迁移与回滚（一致快照、追平、可演练回滚） | 8 | 0=不可回滚;3=可演练;5=含生产量级彩排 | 维度8 |
| 6→ 7 | 运维与可观测性（runbook、指标、告警、值守） | 7 | 0=非开发者无法运维;3=可重复;5=真实告警定位+滚动升级 | 维度7 |
| 7→ 8 | 工程与维护（vtable 边界、旁路、CI、维护成本） | 6 | 0=RonDB 硬编码难隔离;3=局限 vtable;5=含弃用计划 | 维度10 |
| 8→ 9 | 安全与合规（加密、最小权限、SBOM、许可、日志脱敏） | 4 | 0=许可/加密阻断;3=满足;5=含威胁建模签署 | 维度9 |
| 9→ 10 | TCO 与战略适配（3–5 年成本、退出成本、锁定） | 2 | 0=锁定不可逆;3=可量化;5=含退出演练 | 维度11+12 |
| — | **合计** | **100** |  |  |

**依据要点**：
- 正确性/协议(20)+一致性(18) 合计 38%——这是"元数据后端"的地基，任一破坏即整体不可用，且计划把"任何协议/数据不变量无法满足"列为硬闸门（一票否决），故权重最高。
- 性能(15) 高但低于正确性——FDB 提交延迟 17x 量级（`fdb-feasibility-01`）是本项目最大不确定项，但它可以通过工程手段（批量提交、连接池）优化，而正确性破坏是结构性的。
- 战略/TCO 仅 2%——计划 OUTCOME 允许 Hybrid/Defer，成本不是首要否决项。
- **权重是草案**：决策方可按业务侧重调整，只要合计 100 且**不降低**正确性/一致性两维之和（建议 ≥ 35%，防止用成本/战略稀释正确性权重）。

**评分方法**（对齐 §08）：每维 0–5；只有附带 REAL 实验编号 + 原始证据位置的维度才可填分；未完成真实验证一律"待评"，不得用文档/PoC 代填。

## 3. 硬闸门（一票否决，已对齐计划 §08，可直接冻结）

任一触发 → 整体结论**不得**给出 Go/Conditional Go，只能"证据不足"或 No-Go：

| 闸门 | 判定 |
|---|---|
| G-GATE-1 协议/数据不变量 | 任一 I-1..I-9 或 NFSv4 协议不变量在真实目标环境无法满足（`fdb-feasibility-02` §B.1） |
| G-GATE-2 不可回滚/数据不一致 | 关键场景无法回滚或无法验证数据一致 |
| G-GATE-3 关键 SLO 不可达 | 关键 SLO 在目标规模下不可达 |
| G-GATE-4 错误语义风险 | 存在无限重试、错误码误映射（G1 类）、未知提交结果无法对账（G2 类）或重复副作用风险（`fdb-feasibility-02` §A.3/§A.4） |
| G-GATE-5 灾备/许可/安全阻断 | 灾难恢复、许可或安全存在不可接受阻断项 |
| G-GATE-6 证据不足 | 任一关键维度（#1–#6）缺少 REAL 验证 |

## 4. 决策规则（对齐 §08，可直接冻结）

- 综合得分 = Σ(维度分 × 权重)/100。
- **Go**：无闸门触发 + 综合分 ≥ 4.0 + 所有"待评"维度补 REAL 验证。
- **Conditional Go**：无致命闸门 + 存在有限高风险项 + 列出限定风险消减清单（每项有责任人 + 复测实验）。
- **Hybrid**：仅部分责任域/新场景采用（如 FDB 只做协调/恢复关键状态，命名空间权威仍 RonDB）。
- **Defer / No-Go**：任一硬闸门触发，或综合分 < 3.0；记录触发条件与复评时间点。
- **门槛值（4.0 / 3.0）是草案**：决策方签署时确定，但建议 ≥ 4.0 才 Go（元数据后端"良好"才有替换价值，"最低线 3.0"只配 Conditional）。

## 5. 争议裁决规则（可直接冻结）

| 情形 | 裁决 |
|---|---|
| 两档证据等级归属有争议 | 就低原则：拿不准 REAL 还是 REFERENCE，按 REFERENCE（不得计分） |
| 维度评分分歧 ≥ 2 分 | 必须附原始证据位置（commit+实验编号+manifest），由决策方指定裁决人一次定夺，不做平均 |
| 是否"达到最低线"有争议 | 以 REAL 实验的**通过标准**（计划 §06 实验组表"执行前填写"）为准，不以主观判断 |
| 权重本身争议 | 回到 §2 依据 + 决策委员会表决；正确性/一致性之和不得低于 35% |
| 环境等价性争议 | 以计划 §01"真实目标环境最低定义"逐项核对；任一关键项不一致 → 结果降为"预验证"，不得计分 |
